DataPulse — Data Quality & Analytics Pipeline
The core problem

Companies receive sales/order/transaction data from multiple sources, and the data is often:

duplicated
incomplete
inconsistent
incorrectly formatted
delayed
containing invalid values

The project answers one central question:

"Can we automatically turn messy business data into a trusted analytics dataset and prove that the data is reliable before it reaches BI?"

This is much better than building another "sales dashboard."

What DataPulse does

Imagine a company receives daily order data:

orders.csv
customers.csv
products.csv

The raw data might contain:

Customer ID missing
Duplicate orders
Negative quantity
Invalid dates
Wrong product IDs
Duplicate customers
Different country formats
NULL prices

Bad data should never silently reach the dashboard.

Level 2 — Data Quality

Add:

Validation Engine

Rules:

customer_id cannot be NULL


quantity > 0


price >= 0


order_date must be valid


customer must exist


product must exist

Create a data_quality_results table.

Level 3 — PySpark

Replace Pandas transformation for larger datasets:

Raw CSV
   ↓
PySpark
   ↓
Cleaned Data
   ↓
Parquet

Generate:

data/
├── raw/
├── processed/
└── quarantine/

Partition Parquet by:

year
month

processed/
  year=2026/
    month=08/

Now you're learning real data engineering concepts.

Level 4 — Airflow

quality_gate

Pipeline
   ↓
Quality = 91%

❌ FAIL

Airflow stops downstream processing.

AWS Mode

This is where we follow your requirement very carefully.

The application shouldn't be written specifically for AWS.

Instead, create an abstraction:

Storage Layer
     │
     ├── LocalStorage
     │
     └── S3Storage

Locally:

LocalStorage

AWS:

S3Storage

Similarly:

Warehouse
   │
   ├── PostgreSQL
   │
   └── Redshift

Processing:

Local Spark
     │
     └── AWS Glue

Trigger:

Airflow
   │
   └── AWS Lambda

So your architecture becomes:

              DataPulse
                  │
        ┌─────────┴─────────┐
        │                   │
     LOCAL MODE          AWS MODE
        │                   │
        ↓                   ↓
   Local Files             S3
   PostgreSQL             Redshift
   Spark                  Glue
   Airflow                Lambda
AWS Configuration

The user shouldn't have to rewrite your code.

Something like:

DEPLOYMENT_MODE=local

Local:

STORAGE_BACKEND=local
WAREHOUSE_BACKEND=postgres
PROCESSING_ENGINE=spark

AWS:

DEPLOYMENT_MODE=aws


STORAGE_BACKEND=s3
WAREHOUSE_BACKEND=redshift
PROCESSING_ENGINE=glue

Then Terraform handles infrastructure.

DataPulse — Data Quality-Aware Cloud Data Engineering Platform

Python | SQL | PySpark | Apache Spark | Airflow | PostgreSQL | Parquet | FastAPI | Power BI | Docker | Terraform | AWS | GitHub Actions

Built an end-to-end data engineering platform that ingests, validates, transforms, and serves large-scale business datasets while preventing low-quality data from reaching analytics systems. Implemented PySpark transformations, Parquet-based data lake storage, Airflow orchestration, automated data-quality gates, quarantine handling, schema validation, and Power BI analytics, with Docker-based local execution and optional Terraform-managed AWS deployment.
